## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Successfully implemented production-grade Postgres backup sync to GCS orchestrated by Kestra + Ansible.

**Architecture (Option B - Container Isolation):**
- Kestra orchestrates workflow in Docker containers
- GCP credentials stay in container (never touch host)
- Ansible SSHs from container to host via Tailscale IP
- Backups fetched to container, uploaded to GCS from there
- gcloud SDK installed on ansible image for proper auth

**Key files:**
- kestra/production/postgres-backup-gcs-sync.yml (5-stage workflow)
- roles/postgres-gcs-backup/ (Ansible role with delegate_to pattern)
- inventory/localhost.yml (host renamed to nixos_host, Tailscale IP)

**Lessons learned across 9 test runs:**
1. 127.0.0.1 in container != host - use Tailscale IP
2. Inventory host named 'localhost' conflicts with delegate_to: localhost
3. Standalone pip gsutil doesn't honor GOOGLE_APPLICATION_CREDENTIALS - use real gcloud SDK
4. Alpine's busybox date lacks -d flag - install coreutils
5. /bin/sh doesn't support bash array syntax
6. Kestra passes vars as strings - use | int filter
7. Split monolithic tasks into stages for easier debugging
8. Write persistent files to {{workingDir}} (volume-mounted across tasks)
